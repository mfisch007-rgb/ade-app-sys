# ADE BLOCK 01 — EXPERIENCE & SAFETY FOUNDATION

**Document Ref:** ADE-ARCH-2026-BLOCK01-EXPERIENCE-FOUNDATION
**Status:** RECONCILED / HARDENED

## Purpose

Block 01 establishes the foundational contracts required for the unified ADE
platform.

## Core Principles

- One platform, not fragmented applications.
- Capability and entitlement driven.
- Server-authoritative safety.
- UI does not own business authorization.
- Progressive verification rather than premature compliance friction.
- Centralized media registry.
- Poster-first and lazy-loaded media.
- Explicit LIVE / SIMULATED / CONCEPT semantics.
- Accessibility does not depend on color alone.

## Verification / Compliance Position

ADE establishes compliance-ready hooks now.

Full KYC/KYB/AML enforcement is activated later according to:

- jurisdiction,
- persona,
- capability,
- financial activity,
- organizational risk,
- partner requirements,
- regulatory obligations.

This prevents unnecessary onboarding friction for public exploration,
community participation and low-risk demonstrations while preserving a path
to production-grade verification.

## Product Theater

ADE Product Theater is not merely a trailer player.

It is the controlled presentation layer for:

- live ADE execution,
- simulated execution,
- conceptual capabilities,
- architecture demonstrations,
- product walkthroughs,
- ecosystem storytelling,
- media/trailer experiences.

Every displayed execution state must explicitly identify whether it is:

✓ LIVE
⚗ SIMULATED
◌ CONCEPT

## Media Registry

Media must be resolved through `lib/core/mediaRegistry.ts`.

React components must not embed arbitrary hard-coded media paths.

Presentation modes include:

- CINEMATIC
- COMPACT
- INLINE
- PREVIEW_POSTER

Heavy media should remain lazy-loaded and poster-first.
