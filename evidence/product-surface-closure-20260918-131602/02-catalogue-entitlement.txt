02 CATALOGUE / ENTITLEMENT RECONCILIATION

Authoritative catalogue sources (existing, no new registry):
  - ProductRegistry ADE_PRODUCTS (4): ade-platform ACTIVE/COMMUNITY, procarta INTEGRATED/plugin, awbuli INTEGRATED/plugin, oracle INTEGRATED/no-plugin
  - ConnectionFabric PRODUCT_CONTRACTS (4): awbuli, procarta, nexus, eventos (grip % from verified required capabilities only)
  - BUILTIN_ECOSYSTEM_CAPABILITIES (13, src/app.js): pluginRequired=false -> ACTIVATED (PROCARTA_WORKFLOW, ECHO_TOGGLE, KERNEL_SHUTDOWN, SECURITY_GATE_VERIFY); credential-gated -> EXTERNAL_CREDENTIAL_REQUIRED; external-gated -> PARTNER_REQUIRED
  - EditionPolicy CAPABILITY_AVAILABILITY (17 intents, COMMUNITY column is the entitlement bit)
  - CapabilityRegistry core (8): PING, PUBLIC_INFO, WATCH_ASSET, TELEMETRY_SSE, UNIVERSAL_AI_GATEWAY, MULTI_STREAM, SYSTEM_HEALTH, SYSTEM_SHUTDOWN (rbacLevel+tier recorded, enforcement upstream)
  - TradingEntitlements resolver: grant/revoke/get/can(userId, trading|gaming), durable store, caller must enforce L2

Why evidence reported CapabilityActivation ENABLED=False: the module uses ACTIVATION_STATES
(AVAILABLE|ACTIVATED|CONFIGURATION_REQUIRED|PARTNER_REQUIRED|EXTERNAL_CREDENTIAL_REQUIRED|PREVIEW|OFFLINE|UNAVAILABLE),
never an ENABLED boolean. The [3/9] checker searched for the literal word ENABLED, so False is an audit artifact, not a defect.
CONFIGURED=True came from code comments ('configure a provider key'), CATALOG=True from catalog language. No booleans were flipped;
GET /api/v1/product-surface now joins the authorities so the UI reads derived states instead of literals.
